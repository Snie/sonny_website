# Documentation: writing & maintenance

How this project's documentation is organized, why, and how to keep it coherent and current.

## Goal

`AGENTS.md` is the single **top-down map** of the project. It must stay small because it loads into
every Claude Code session in full (`CLAUDE.md` is just `@AGENTS.md`). Everything else loads **on
demand** so the always-on token cost stays low. Both a human and an agent should be able to read
`AGENTS.md` alone and know *where* to find any detail.

## Ownership

The human owns the WHAT and WHY — the product spec (`docs/specs.md`) and the conventions
(`.claude/rules/`). These are hand-edited and authoritative. The agent owns navigation: it consults
the [Where to find things](../AGENTS.md#where-to-find-things) index to know which file governs the
task at hand, and loads it (path-scoped rules load automatically when matching files are touched).
This keeps control with the human while the agent always knows what to look for.

## What loads when (the mechanics)

| Mechanism | Loads | Use for |
| --- | --- | --- |
| `AGENTS.md` (via `@AGENTS.md` in `CLAUDE.md`) | Every session, in full | The map + always-true conventions |
| `@import` / `@path` | Every session, in full (recursive, max 4 hops) | Avoid for large files — it does **not** save tokens |
| `.claude/rules/*.md` with `paths:` frontmatter | Only when a matching file is touched | Conventions tied to specific file types |
| `.claude/rules/*.md` without `paths:` | Every session | Avoid unless truly always-relevant |
| Skills (`.claude/skills/*/SKILL.md`) | Only when invoked or judged relevant | Procedures and workflows |
| `docs/*.md` referenced by **plain path** (not `@`) | Only when the file is read | Deep reference material |

Key rule: **never `@`-import large reference files** into `AGENTS.md`. Point to them by plain path
(e.g. `` `docs/specs.md` ``) so they load only when read.

## Maintenance rules

- **README vs AGENTS.md**: `README.md` is for humans (quick start, project description,
  contribution guidelines). `AGENTS.md` is the agent/contributor map and points to depth. Do not
  duplicate content between them.
- **No duplication anywhere**: a fact lives in exactly one place; everything else points to it.
- **Markdown lint**: after writing or editing any markdown file, run `markdownlint-cli2` and fix all
  violations. The `specs/` folder is exempt.
- **Changelog**: `CHANGELOG.md` follows the Keep a Changelog standard and is generated by
  semantic-release from conventional commits — do not hand-edit it. Documentation changes land there
  via a `docs:` commit.
- **Keep it coherent**: when a path, file, or convention changes, update the map and the relevant
  rule/skill/doc in the same change. Stale pointers are worse than no pointers.
